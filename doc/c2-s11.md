# C2-S11: String.prototype.replaceAll

Status: landed on Mac no-JIT. Unconditional library method. No feature
flag and no kill switch. `String.prototype.matchAll` is not in this batch.
JIT evidence is not claimed; see B4 below.

## Supported configuration

- Default Mac profiles (test and debug-static): `replaceAll` is present.
  `ES6RegExSymbols` and `ES6RegExPrototypeProperties` are off, so
  `@@replace` is not consulted and `RegExp.prototype.flags` is absent.
  A real regexp uses its internal global bit.
- `-ES6RegExSymbols`: after the `IsRegExp` / `flags` check, `@@replace`
  is read only when the search value is an Object. Primitives do not
  consult `String.prototype[@@replace]` or the other primitive
  prototypes. This flag is not the default.
- `-ES6RegExPrototypeProperties`: installs the builtin `flags` getter.
  `replaceAll` then `Get`s it. Not required for the default behavior.
- No kill switch. Removing the method would be a library change, not a
  flag. Precedent: `String.prototype.at`.

## What landed

- Unconditional library method on `String.prototype`, installed with
  `AddFunctionToLibraryObjectWithPropertyName` under a tracked dynamic
  property id. No `builtinFuncs[]` slot, no static `PropertyIds::replaceAll`,
  no bytecode or opcode change, no Backend/JIT helper, and no new `TypeId`.
  `JavascriptBuiltInFunctionList.h` registers
  `BUILTIN(JavascriptString, ReplaceAll, EntryReplaceAll, FunctionInfo::ErrorOnNew)`.
  That is the runtime entry id (`new` throws). It is not an opcode and
  not a bytecode constant. `InitializeStringPrototype` passes `40` to
  `DynamicTypeHandler::Convert` as a property-capacity hint, not as a
  count of own properties.
- Gate and doc files that moved with the two new es7 tests (1962/2014
  was S5; this batch is 1964/2016): `tools/build/check_regression.py`,
  `build.zig`, `.github/workflows/zig-macos.yml`, `doc/memory-management.md`,
  `doc/c1-triage.md`, `doc/modernization-plan.md`. `.gitattributes` gives
  `*.baseline` `whitespace=cr-at-eol` so CRLF snapshot lines are not
  trailing-whitespace errors. Two debugger snapshots list `replaceAll`:
  `test/DebuggerCommon/ES6_proto_invalidation.js.dbg.baseline` and
  `test/DebuggerCommon/TempStrExpr.js.dbg.baseline`.
- Symbols off: `@@replace` is not consulted. After the IsRegExp flags
  check, a real regexp that passed it uses `RegexHelper::RegexReplace` /
  `RegexHelper::RegexReplaceFunction`. A missing `flags` property on a
  real regexp uses the internal global bit. An own or inherited `flags`
  value is `Get`'d. `undefined` or `null` throws `TypeError`
  (`JSERR_NeedObject`). A non-global regexp throws `TypeError`.
- Symbols on: IsRegExp runs first, and only then the flags check, before
  `@@replace` is read. `@@replace` is then read only for an Object search
  value, including a plain object and a regexp whose `@@match` is false.
  A string, number, boolean, or symbol primitive does not read
  `@@replace`. A missing or null `@@replace` on an object falls through
  to the string path, including for a real regexp. A non-callable
  `@@replace` throws `TypeError`. `String.prototype.replace` still reads
  `@@replace` on primitives; that is pre-existing and not part of this
  batch (S7 regexp-symbol cluster).
- An empty search does not use `strstr`. It matches every boundary,
  including both ends.
- The position list is a temp-allocator array released by RAII. The result
  is `CompoundString::Builder::ToString()` before that arena is released.
  The `$` scan in `DoStringReplaceAll` is a third copy of the empty-capture
  scanner already in `RegexHelper::StringReplace` (the helper itself is
  duplicated there). No output divergence was found against the string-path
  cases. Sharing one `GetSubstitution` helper is debt, not this batch.

## Limits

These are platform or pre-existing gaps. They are not open S11 defects.

- Absent `flags`. Spec and Node `Get` `flags` and throw when the result
  is `undefined` or `null`, including after `delete RegExp.prototype.flags`.
  This build, when `flags` is missing on the regexp and its prototype
  chain, uses the internal global bit and does not throw. That is how
  the default profile, which never installs `RegExp.prototype.flags`,
  can still replace every match of `/a/g`. When the property is present
  (own, inherited, or `-ES6RegExPrototypeProperties`), `Get` runs and
  `undefined` / `null` throw.
- Named capture groups are not implemented. A pattern such as
  `(?<named>b)` throws `SyntaxError: Unexpected quantifier` from the
  regexp parser. In the string replacement, `$<name>` stays literal,
  including the `$`. `test/built-ins/RegExp` named-group `replaceAll`
  tests cannot pass on this build. The in-corpus file
  `searchValue-replacer-RegExp-call.js` reaches that pattern only when
  `-ES6RegExSymbols` lets the subclass `@@replace` run.
- `ESBigInt` is off. `cstm-replaceall-on-bigint-primitive.js` fails to
  parse (`Unexpected identifier after numeric literal`). The file is
  tagged `Symbol.replace` and not `BigInt`, so `analyze.py` buckets it
  as `disabled-flag` and a Symbol.replace exclusion hides the parse error.
- `String.prototype.replace` still looks up `@@replace` on primitive
  search values. `replaceAll` does not. The `replace` behavior is
  pre-existing debt.
- `String.prototype.replace` still reports `arguments.length === 1` when
  the replacement is omitted (`CallRegExFunction`). `replaceAll` passes
  an explicit `undefined`, so a custom `@@replace` sees length 2.
- TypeError text differs from Node (`invalid argument` versus a
  non-global RegExp message; `null or not an object` versus null or
  undefined). Tests check the error type only.
- `tools/build/check_regression.py` still feeds `Total: passed 2014`
  into the test expectation as a negative fixture. That line must keep
  rejecting.
- Three regexp-like cases in `test/es7/replaceall.js` return immediately
  when `Symbol.match` or `Symbol.replace` is undefined, so the default
  rlexe launch does not run them. The same cases run from
  `test/es7/replaceall-symbols.js`.

## Ownership

Resource: the match-position array and the copied replacement text,
`AnewArray` on the temp arena inside `DoStringReplaceAll`
(`JavascriptString.cpp`, `ReplaceAllTemp`).

- Domain: `ScriptContext::GetTemporaryAllocator("replaceAll")`, released
  by `ReleaseTemporaryAllocator` in the destructor. Not a GC object.
  Not retained past the call.
- Owner: the stack `ReplaceAllTemp`. Copy and assignment are deleted.
  The builder's `ToString()` runs before the guard ends, so the result
  string is a recycler string and does not borrow the arena.
- Invalidation: destructor on success, on a JS exception from the
  replacer or from `ToString` of a function result, and on unwind.
  A replacer may call `replaceAll` again; each call takes its own
  allocator. Nested depth 8 (past the small temp-allocator cache) and
  a throw from the inner call both leave a later `replaceAll` working.
- User code: the functional replacer and `ToString` of its result.
  Positions are already stored as integers. The `$` scan uses the
  copied `char16` buffer, not a `GetString()` pointer that `Append`
  could flatten.
- Thread: the calling script context only.
- Bound: one array of `matchCount` `CharCount`s plus one copy of the
  replacement. `matchCount` for an empty search is `inputLength + 1`.
  A 4000-match throw at match 50, then a full replacement of that
  input, is the in-tree lifetime test.
- Not claimed: OOM injection, `-RecyclerStress`, or a JIT allocation
  profile. `-RecyclerStress` is a pre-existing mode that corrupts
  untouched builtins.

## JIT (B4)

All evidence here is Mac no-JIT. `replaceAll` is an ordinary runtime
library call: no new opcode, no bytecode change, no Backend helper, and
nothing for a JIT to lower inline. The dynamic property id is not a
bytecode constant slot. Per the plan, B4 must still run this test262
corpus and both es7 files under SimpleJIT and FullJIT (dynapogo) before
any JIT-configuration claim. Also check inline-cache invalidation after
patch or delete of `replaceAll`, and that the temp arena is not kept
alive across a JIT call. There is no kill switch to flip if that fails.
