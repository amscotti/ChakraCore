### 1.1 JIT+WASM UBSan `29/29` (`lib/Backend/ObjTypeSpecFldInfo.h`, `lib/Backend/Opnd.h`)

- **`ObjTypeSpecFldInfo` null-`this` constructor guards (`lib/Backend/ObjTypeSpecFldInfo.h:73-139`):**
  - `ObjTypeSpecFldInfo::CreateFrom` (`lib/Backend/ObjTypeSpecFldInfo.cpp:686, 700, 1112`) passes optional `nullptr` values for `initialType`, `propertyGuard`, `ctorCache`, `fixedFieldInfoArray`, and `polymorphicInfoArray`. Previously both parameterized `ObjTypeSpecFldInfo` constructors invoked `->GetData()`, `(void*)->GetAddressOfValue()`, and `->GetRaw()` unconditionally on null pointers, failing `15/29` JIT+WASM UBSan legs under `halt_on_error=1`.
  - **Fix:** Null-guard all five optional pointer parameters before invoking their accessor methods (`initialType ? initialType->GetData() : nullptr`, `propertyGuard ? (void*)propertyGuard->GetAddressOfValue() : nullptr`, `ctorCache ? ctorCache->GetData() : nullptr`, `fixedFieldInfoArray ? fixedFieldInfoArray->GetRaw() : nullptr`, `polymorphicInfoArray ? polymorphicInfoArray->GetRaw() : nullptr` at lines `94-103` and `128-138`), and add the `ChakraCore Project Contributors` copyright header.
- **`IndirOpnd` uninitialized boolean field (`lib/Backend/Opnd.h:1676`):**
  - `IndirOpnd::IndirOpnd()` omitted `m_conversionAllowed` in its member initializer list, and `IndirOpnd::New(RegOpnd *indexOpnd, int32 offset, byte scale, IRType type, Func *func)` (`lib/Backend/Opnd.cpp:2500-2518`) left it uninitialized on arena-allocated memory. `IR::IndirOpnd::CopyInternal` (`lib/Backend/Opnd.cpp:2601`) then loaded a non-boolean byte (`-fsanitize=bool`) on `3/29` JIT+WASM UBSan legs.
  - **Fix:** Initialize `m_conversionAllowed(false)` directly in `IndirOpnd::IndirOpnd()`, covering every `IndirOpnd::New` factory path uniformly, and add the `ChakraCore Project Contributors` copyright header.

### 1.2 `-ParserStateCache` `ImmutableList` Null-Receiver UBSan Fix

- **Root cause (`doc/open-cards.md` §17):** `regex::ImmutableList<T>::Empty()` returns `nullptr`. Calling member methods (`Prepend`, `ReverseCurrentList`, `Accumulate`, `Iterate`, `FreeList`, `Append`, `AppendArrayToCurrentList`, `IsEmpty`) on `nullptr` receivers triggered UBSan null-`this` errors -- notably `ByteCodeBufferBuilder::PrependConstantInt32` in `test/Function/bug_os17698041.js` under `-ParserStateCache`.
- **Fix:**
  - `lib/Common/DataStructures/ImmutableList.h`: Added static null-safe helpers (`FreeList` `:23-31`, `Prepend` `:48-51`, `Append` `:62-88`, `AppendArrayToList` `:119-127`, `Iterate` `:344-354`, `Accumulate` `:406-418`, `Reverse` `:454-467`, `ReverseCurrentList` `:478-490`, `Count` `:650-662`, `IsEmpty` `:827-830`), and migrated internal traversals and instance wrappers to call the static helpers so `nullptr` is passed as an explicit pointer argument rather than as `this`.
  - `lib/Common/DataStructures/BufferBuilder.h:243-256`: Updated `BufferBuilderList::FixOffset` and `BufferBuilderList::Write` to invoke `regex::ImmutableList<BufferBuilder*>::Accumulate` and `Iterate`.
  - `lib/Runtime/ByteCode/ByteCodeSerializer.cpp:449-457, 769-778`: Added `ByteCodeBufferBuilder::{PrependNode, ReverseList}` delegating to static `ImmutableList` helpers and replaced every nullable `builder.list->Prepend` / `builder.list->ReverseCurrentList` call (including `PrependConstantInt32`).

### 1.3 ARM64 `LowererMD::GenerateFastInlineBuiltInMathFloorCeil` `-0` Fix & `MathLibrary.cpp` UBSan Guard

- **ARM64 JIT `-0` root cause (`lib/Backend/arm64/LowerMD.cpp:9216-9302`):**
  - Previously `GenerateFastInlineBuiltInMathFloorCeil` toggled the sign bit (`EOR #0x8000000000000000`) and checked `CBZ negZeroReg`, which only matched `floatOpnd == -0.0`. Negative fractional inputs in `(-1.0, -0.0)` under `Math.ceil` (such as `-5e-324` and `-0.5`) converted via `FCVTP` to `intOpnd = 0` without bailing out, returning `+0` instead of `-0` (failing `4/4` Test262 `Math/{ceil,floor}` scenarios `S15.8.2.6_A7.js` and `S15.8.2.9_A7.js` under `-ForceJITLoopBody -maxinterpretcount:1`).
  - **Fix:** Capture `FMOV_GEN negZeroReg, floatOpnd` before `FCVTM`/`FCVTP` and replace `EOR` + `CBZ` with `CBNZ intOpnd, checkOverflowLabel` -> `TBZ negZeroReg, #63, checkOverflowLabel` -> `B bailoutLabel` -> `checkOverflowLabel:` -> `TBZ exceptReg, #0, doneLabel`. Every negative input whose rounded integer is `0` (`-0.0`, or `(-1.0, -0.0)` under `Math.ceil`) bails out to preserve `-0`, while non-negative `intOpnd == 0` inputs (including `+NaN`) continue through the `FPSR.IOC` overflow check (`TBZ exceptReg, #0, doneLabel`).
  - **Regression (`test/Optimizer/arm64_math_floor_ceil_negzero.js`):** Added in [test/Optimizer/rlexe.xml](../test/Optimizer/rlexe.xml), covering `(-1, -0]`, `+-0`, `+-1`, `+-NaN` (`0x7ff8000000000000` / `0xfff8000000000000`), `+-Infinity`, `+-0x80000000`, `+-2^32`, subnormals, `| 0` (`ignoreNegativeZero`), shared bailout pairs, SimpleJIT, FullJIT, and LoopBody JIT. Pre-fix `4c6a6b475` failed on `input=-5e-324` (`expected -0, got +0`) and scored `40/4` on Test262 `Math/{ceil,floor}` under `-ForceJITLoopBody -maxinterpretcount:1` (`44/0` under `-nonative`); post-fix scores **`44/0` in both modes (`0` diffs)**.
- **Runtime `Math::Ceil` / `Math::FloorDouble` UBSan float-cast guard (`lib/Runtime/Library/MathLibrary.cpp:335-343, 411, 615-620`):**
  - Running `arm64_math_floor_ceil_negzero.js` under `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1` uncovered pre-existing UB in `Math::Ceil` (`MathLibrary.cpp:399`) and `Math::FloorDouble` (`MathLibrary.cpp:616, 621`), which unconditionally cast `(intptr_t)result` on `+-Infinity` (`runtime error: inf is outside the range of representable values of type 'long'`).
  - **Fix (`f627c4522`):** Extracted `IntegerDoubleToVar(double result, ScriptContext* scriptContext)` (`MathLibrary.cpp:335-343`) using `JavascriptNumber::TryGetInt32Value` (`lib/Runtime/Library/JavascriptNumber.h:69-91`, which range-checks `[-2147483648.0, 2147483647.0]` and excludes `-0.0` before casting) for `Math::Ceil` and the non-fast-path `Math::FloorDouble` (`d > 0.0 && d < 2147483648.0` preserves the direct truncation fast path without UB).
