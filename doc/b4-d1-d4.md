## 1. What changed

### D1 — suspended-coroutine reparse guard, portable

`lib/Common/CommonDefines.h`: `ENABLE_SUSPENDED_COROUTINE_REPARSE_GUARD` is
now gated on `GLOBAL_ENABLE_WRITE_BARRIER` instead of
`__APPLE__ && _M_ARM64`. The guard's release path is
`JavascriptGenerator::Finalize` → `ReleaseLiveCoroutineFrame`, and the
finalized-allocation arm that installs it is compiled under exactly that
macro, so the pairing is unchanged. Non-Windows builds define the write
barrier and therefore now get the guard on Linux x64; Windows keeps it for
`ForceSWB` builds (which also have the finalizer) and default builds stay
off. The Mac behavior is byte-identical (the macro was already 1 there).

`test/DebuggerCommon/AsyncSuspendedDetach.js` (new): a plain async function
suspended at `await` and a generator suspended at `yield` are carried
through dynamic attach **and** detach; the generator completes inside the
detach callback and the second async invocation runs on the fresh debug
body. It also creates a suspended generator, drops it, runs
`CollectGarbage()` twice, and then continues, exercising the finalizer
release path (the guard's release half). Tagged `exclude_dynapogo`;
`exclude_linux` was **removed** from this test and from
`AsyncSuspendedResume.js` so the Linux interpreted gate actually exercises
the new activation.

### D2 — exact Number formatting for every requested digit count

`lib/Common/Common/NumberUtilities.h` now defines
`NUMBERUTILS_EXACT_FORMATTING` from `<charconv>` availability plus
libc++ ≥ 14000 / libstdc++ ≥ 20210427 / MSVC ≥ 19.24.

`lib/Common/Common/NumberUtilities_strtod.cpp` adds an exact
double→decimal path:
- `std::to_chars(scientific, 767)` exposes the complete exact significant
  digit string (a double has at most 767 significant decimal digits);
- `RoundExactDigits` rounds the magnitude half up, matching the spec's
  "pick the larger n" and the engine's existing negative-value behavior;
- renderers produce fixed, exponential and precision forms, including
  zero, `-0`, subnormals, carry chains, and the `e < -6` / `e >= p`
  notation switches;
- `FDblToStr` dispatches **every requested-digit call** (`nDigits >= 0`)
  through this path; only the shortest `-1` forms (`toExponential()`,
  `toLocaleString`'s fixed form) remain on the legacy BCD path.
- `lib/Runtime/Library/JavascriptNumber.cpp` accepts the ES2018 ranges
  (0..100 fractional digits, 1..100 significant digits) when the exact
  path exists, and keeps the old 20/21 RangeError caps on fallback
  toolchains.

Cost measured on the pinned toolchain: ~181 ns/call for the 767-digit
expansion, ~41 ns/call at 16 digits; the full expansion is used for
unconditional exactness.

### D3 — exact integer radix conversion

`lib/Common/DataStructures/BigUInt.{h,cpp}`: `DivRemSmall(uint32)` divides
in place and returns the remainder, preserving `AssertValid`
(leading-zero trim, allocation-free).

`NumberUtilities_strtod.cpp` `FNonZeroFiniteDblToStr(dbl, radix, …)` now
builds the integer part as a `BigUInt` from the mantissa and binary
exponent and repeatedly divides by the radix, instead of the lossy
double-division loop. The fractional part still uses the legacy loop on
the exact fraction; radix ≠ 10 remains implementation-defined, and the
integer part is now exact.

### D4 — deferred WASM body validation

`lib/Runtime/Library/WebAssemblyModule.cpp`: deferred bodies are now
validated at construction with `WasmBytecodeGenerator::ValidateFunction`
(the validate-only empty writer), so an invalid body cannot construct a
Module that only throws on first call.

`lib/WasmReader/WasmByteCodeGenerator.cpp`: `EnregisterLocals` no longer
calls `FunctionBody::SetFirstTmpReg` while validating. The field is
one-shot (the `FunctionBody` setter asserts it is not reset), and the
deferred compile of the same body runs the path again; validation must not
consume it. The real compile still publishes the layout.

`test/wasm/deferred-invalid-body.js` (new): invalid-opcode body must throw
at `new WebAssembly.Module`; a valid empty module still instantiates; an
exported `() -> i32` body returning 42 is constructed, instantiated and
called twice (forcing the deferred compile); an import/instance module
calls through an imported function (the shape that forced the earlier
eager-validation revert). This file is `require_backend`/WASM-only and
cannot run on this Mac ARM64 build.

## 3. Ownership record (per [memory-management.md](memory-management.md))

| Resource | Domain / allocator | Owner; invalidation | Notes |
|---|---|---|---|
| D1 retained suspended `FunctionBody` | Recycler, finalizable | Each `JavascriptGenerator`'s `Field(FunctionBody*) liveCoroutineFunctionBody`; released on completion or the generator finalizer | Pre-existing Mac contract, newly activated on Linux x64 by the macro change. The new test exercises completion and a collected suspended generator (`CollectGarbage`). |
| D1 frame count | Plain `uint` on `FunctionBody` | `AddLiveCoroutineFrame` from `SetFrame`; decremented from completion/finalizer | Allocation-free; one decrement per counted generator; shutdown skips release by design (context teardown). |
| D2 digit buffers | Stack: `char[799]` (to_chars output), `char[768]` (digits), `char[512]` (rendered), plus the existing 256-char16 caller buffer | Stack frame; no heap | `to_chars` is allocation-free and returns `errc`; the exact renderer returns the required length without writing when the caller buffer is short, preserving `FDblToStr`'s contract; `FormatDoubleToString`'s existing malloc-retry path frees its buffer. |
| D3 `BigUInt` integer part | Stack object + optional `malloc` in `BigUInt::FResize` (max growth to 60 limbs for a 1024-bit integer) | Destructor frees; all early returns are after the object is constructed | `DivRemSmall` is allocation-free and trims leading zero limbs. Output `char16 reversed[1100]` holds the 1024-digit base-2 worst case; the JS caller's `bufSize` is 1280. |
| D4 validation generator | `ArenaAllocator` on the thread context page allocator, local to `WasmBytecodeGenerator` | Destroyed at end of validation; no new retained allocation | Validation uses the empty writer; `SetFirstTmpReg` is suppressed; `SetExitLabel` is a plain field overwritten by the real compile. The shared module reader is re-seeked by the deferred generator's constructor. |

Threads/contexts: all four lanes run on the script thread; D2/D3 do no
GC-relevant allocation (D3's `BigUInt` is native heap, not recycler); D1's
retention is the existing recycler contract; D4 validation runs during
module construction on the script thread.

## 4. Review record

Both mandated reviews ran read-only against the working tree. Both
initially returned **REJECT**; every actionable finding was fixed and the
gates re-run:

- **D4 debug assert:** validation published `FunctionBody::firstTmpReg`
  via `SetFirstTmpReg`; the deferred compile then asserted. Fixed by
  guarding the call with `!IsValidating()`; the new exported-call test
  exercises the second compile.
- **Portability:** the exact path is feature-gated; the API caps now
  follow the same macro (100/100 vs 20/21) so fallback toolchains throw
  instead of emitting wrong digits; the feature macro lives in the shared
  `NumberUtilities.h` with version bounds.
- **Low-digit exactness:** the exact path was extended from >15 digits to
  every requested digit; this fixed the 15/14-digit residuals and the two
  remaining test262 `toPrecision` failures, and required the `redefer`
  baseline regeneration.
- **D1 coverage:** the generator now completes inside the detach callback,
  and a dropped suspended generator + `CollectGarbage()` exercises the
  finalizer; `exclude_linux` removed from both D1 tests.
- **Nit folds:** Windows ForceSWB comment corrected; expected-output
  comments regenerated; CRLF restored on the two modified legacy tests;
  D4 test gained an imported-function module.

Final verdicts: **ACCEPT (Mac-side)** from both reviewers, with the Linux
native run as the remaining gate.

## 6. Residuals

- `Number::toString` shortest-representation low digits for |x| ≥ 1e21
  remain the pre-existing `ToStringRadix10` behavior (e.g.
  `7.190013347548976e+256` vs Node's `…977e+256`); `toFixed` correctly
  delegates to `ToString` there per spec. Not introduced or worsened by
  this batch; needs a shortest-representation lane, not the exact
  requested-digit formatter.
- D1's suspended frame cannot hit breakpoints inside the already-suspended
  body until it completes (the original retained body has no probes); the
  fresh debug body serves new invocations and the function is fully
  debuggable from the attach onward. Same tradeoff as the Mac fix.
- D4 validation still uses the shared module reader and leaves
  `SetExitLabel` set (overwritten by the real compile); only the Linux
  native run can prove the import/instance and debug-assert paths.
- The Linux pins and the D1 `exclude_linux` removal are deliberately a
  handoff: the Mac cannot prove the Linux host message loop or WASM x64.
